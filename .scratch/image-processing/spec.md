# 本地图像处理网页

Status: ready-for-agent

## Problem Statement

用户需要在电脑或手机浏览器中处理设备上的源图片，却不希望文件上传到任何服务器。现有工具常把 PDF 转换、水印、批量处理、移动端使用拆散，或要求安装原生应用。用户需要一个中文、纯静态、本地运行的网页：能选择设备文件，导出 PDF，添加可配置文字水印，并在桌面和移动端遵循不同但清晰的导出流程。

## Solution

交付一个使用当前稳定版 Vite、React、Vitest、shadcn/ui 构建的响应式静态网页。浏览器在处理会话内读取源图片，Canvas 生成文字水印结果，pdf-lib 或 jsPDF 生成 PDF；源图片与导出文件均不经过服务器。

桌面支持多选。每张源图片生成一个独立 PDF，按选择顺序打入 ZIP；批量水印把同一套配置按相对位置应用至每张图，并将批量结果打包。移动端只支持单选、单图导出，通过浏览器下载或系统分享交付 PDF 到文件系统。

## User Stories

1. 作为桌面用户，我想从电脑文件系统选择多张源图片，以便批量处理本地图片。
2. 作为移动用户，我想从手机文件系统选择一张源图片，以便在手机浏览器中完成处理。
3. 作为移动用户，我想在尝试多选时得到明确限制提示，以便知道移动端单图导出边界。
4. 作为用户，我想在处理前知道源图片不会上传，以便放心处理私密文件。
5. 作为用户，我想在当前处理会话中看到所选源图片，以便确认处理对象。
6. 作为桌面用户，我想在缩略图列表中切换当前源图片，以便检查批量任务中的每一张图。
7. 作为桌面用户，我想在中间预览区看到当前源图片和水印效果，以便在导出前确认结果。
8. 作为用户，我想把一张原图直接转换为 PDF，以便不添加水印也能完成转换。
9. 作为桌面用户，我想让每张源图片生成一个独立 PDF，以便每个文件保持独立。
10. 作为桌面用户，我想把多个独立 PDF 打包为一个 ZIP 下载，以便一次取得批量导出结果。
11. 作为移动用户，我想把单张源图片导出为一个 PDF，以便保存或分享给其他 App。
12. 作为移动用户，我想通过下载或系统分享把 PDF 交付到文件系统，以便不依赖“相册”存放 PDF。
13. 作为用户，我想输入文字水印内容，以便标识图片用途或归属。
14. 作为用户，我想自由拖拽文字水印，以便将其放到任意合适位置。
15. 作为用户，我想让拖拽后的文字水印始终完整位于源图片内，以便导出结果不出现截断文字。
16. 作为用户，我想设置文字水印字号，以便平衡可读性和对图片内容的遮挡。
17. 作为用户，我想设置文字水印颜色，以便适配不同图片背景。
18. 作为用户，我想设置文字水印不透明度，以便水印可见但不过度遮挡内容。
19. 作为用户，我想设置文字水印旋转角度，以便满足常见斜向水印需求。
20. 作为用户，我想切换重复水印模式，以便让文字以固定网格密度覆盖整张图片。
21. 作为用户，我想在重复水印模式中看到全图预览，以便确认覆盖效果。
22. 作为桌面用户，我想把同一套文字水印配置批量应用到所有源图片，以便高效处理多张图片。
23. 作为桌面用户，我想让批量水印位置按每张图片的相对坐标应用，以便不同尺寸图片仍保持一致布局。
24. 作为用户，我想导出已加文字水印的 PNG，以便保留无损或高质量图片。
25. 作为用户，我想导出已加文字水印的 JPEG，以便在文件大小与兼容性间平衡。
26. 作为用户，我想导出已加文字水印的 WebP，以便在支持该格式的场景中使用更高压缩效率。
27. 作为用户，我想把加水印后的图片转为 PDF，以便在同一处理会话完成最终交付。
28. 作为用户，我想让 PDF 页面与图片比例一致、图片铺满且无白边，以便不被固定 A4 版式改变内容呈现。
29. 作为用户，我想让导出文件保留源文件基础名并追加功能后缀，以便容易识别结果。
30. 作为用户，我想让同名导出文件自动编号，以便批量导出不会覆盖或混淆结果。
31. 作为用户，我想在浏览器不支持、文件是动图、文件超过 20 MB 或最长边超过 8,000 px 时得到清晰错误提示，以便修正输入而非得到失败导出。
32. 作为用户，我想在刷新或关闭页面后自动清除处理会话，以便本地临时数据不被持久保存。
33. 作为中文用户，我想使用全中文浅色界面，以便无需切换语言或理解英文工具文案。
34. 作为用户，我想在深灰棋盘预览背景中辨认图片边界，以便处理透明或浅色图片。
35. 作为维护者，我想让 Pull Request 和 main 分支都自动运行测试，以便合并前发现回归。
36. 作为维护者，我想让 main 分支测试通过后自动部署到 GitHub Pages，以便线上静态站保持同步。

## Implementation Decisions

- 产品是纯静态浏览器应用。遵循 ADR-0001：不设置图片处理后端、不使用 Python Pillow、不上传源图片或导出文件。
- 处理会话只存在于页面内存。刷新、关闭页面即清除；不使用 LocalStorage、账户或云端会话。
- 使用当前稳定版 Vite、React、Vitest、shadcn/ui。界面只提供简体中文、浅色主题；不做国际化或深色主题。
- 使用浏览器文件选择能力读取源图片。输入范围是浏览器可解码的静态图；拒绝动图、超过 20 MB 的文件、最长边超过 8,000 px 的图像。
- 桌面允许多选；移动端限制单选。响应式界面在桌面呈现缩略图列表、当前图 Canvas 预览、水印设置和导出区；移动端呈现单图优先流程。
- Canvas 是水印渲染与预览的一致性边界。文字水印配置包含内容、相对位置、字号、颜色、不透明度、旋转角度、是否重复，以及预留的 `horizontalSpacing`、`verticalSpacing`。字体固定系统无衬线字体。
- 单次文字水印通过拖拽定位。渲染层必须限制旋转后文字外接范围，使文字完整留在图片内部。
- 重复水印以固定网格密度平铺整张图。首版不提供间距控件；保留间距字段供后续扩展。重复模式不使用单次拖拽位置作为输出位置。
- 桌面批量水印把一套配置按相对坐标应用到每张源图片。批量 PDF 或批量水印图片分别打包为 ZIP；PDF 永远一图一个文件并保持选择顺序。
- 支持原图 PDF 导出与水印 PDF 导出。PDF 页面按图片比例创建，图片铺满页面、无白边、无固定 A4 选项。
- 水印图片导出格式固定为 PNG、JPEG、WebP；批量结果使用 ZIP。导出名称保留基础名并追加功能后缀；同名自动编号。
- 使用 PDF 生成库（pdf-lib 或 jsPDF）和 ZIP 生成库完成浏览器内导出。依赖版本在实现时锁定为当时稳定可用版本。
- 遵循 ADR-0002：GitHub Actions 在 Pull Request 与 main 运行测试；仅 main 测试、构建成功后部署 GitHub Pages。
- 支持范围为桌面 Chrome、Edge 与 iOS、Android 主流浏览器；Firefox、旧版浏览器不在兼容承诺内。

## Testing Decisions

- 好测试只验证用户可见行为、导出产物与错误结果；不锁定组件树、内部 state、Canvas 私有实现细节。
- 主要验收 seam 是浏览器 UI。Playwright 在桌面与移动视口覆盖选图、预览、拖拽文字水印、重复水印、图片导出、原图 PDF 导出、水印 PDF 导出、桌面批量 ZIP、移动端单图限制和错误提示。
- Vitest 覆盖无法稳定依赖浏览器端到端断言的纯规则：文件资格检查、相对位置与边界限制、重复水印配置、导出命名和批量顺序。
- 测试验证导出产物类型、文件名、ZIP 内容、PDF 页数与页面比例等外部可观察结果；必要时使用受控图片 fixture。
- 当前仓库没有既有模块或测试。新测试以用户界面 seam 为首个验收边界，不引入低层实现耦合的测试结构。
- CI 在 Pull Request 与 main 执行 Vitest、Playwright 与构建；部署 job 仅在 main 成功后运行。

## Out of Scope

- 图片上传、后端 API、Python Pillow、账户、登录、云端会话、LocalStorage、跨设备同步。
- 动图处理或导出；图片水印、Logo 水印。
- 移动端多选、移动端批量导出、将 PDF 存入系统相册。
- PDF 固定 A4、白边布局、多张图片合成同一个 PDF。
- 首版重复水印间距控件、可选字体、深色模式、国际化、PWA 安装与离线 Service Worker。
- Firefox 与旧版浏览器兼容承诺。

## Further Notes

- PDF 并非照片相册格式。移动端 PDF 交付应使用浏览器下载到“文件”或系统分享菜单。
- 术语与边界以根目录 `CONTEXT.md` 为准；架构约束以 ADR-0001、ADR-0002 为准。
- 导出格式所需编码能力受目标浏览器支持影响；不支持的编码路径需在界面中清晰提示。
